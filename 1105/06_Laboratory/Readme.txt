
1. The game must generate large numbers of similar 3D entities such as trees, rocks, buildings, enemies, vehicles, or decorative objects. These entities often share the same initial attributes, textures, physics settings, and rendering parameters. It has been observed that creating each object from scratch causes noticeable delays when loading a level or spawning large collections of objects. The solution must provide a faster way to create new instances starting from already prepared model instances.

2. The game must allow players to create and customize a superhero avatar with many configurable attributes, including name, alignment, life points, armor, left-hand weapon, right-hand weapon, special power, ultimate power, movement type, defense level, and status effects. The superhero object has many attributes, some mandatory and some optional. The game needs a solution that allows flexible object construction without long unreadable constructors, while ensuring that required fields are not omitted.

3. The game will include multiple categories of entities, such as space objects, spaceships, aliens, drones, weapons, and obstacles. Each category contains several concrete types with different internal attributes and different initialization rules. The game logic modules must be able to request the creation of game entities without depending on the exact concrete classes, constructor signatures, or initialization details of each object type. Developers need a creation mechanism that hides these details, reduces coupling, and allows new object types to be added without changing the client code that creates them.
